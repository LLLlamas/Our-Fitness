# Map: Workouts (Train tab)

Exercises, rep counter / hold timer, set editing, live sessions, optional Pilates/Yoga/Stretching sections, cardio logging, Live Activity, exercise MET data, on-device-AI workout suggestions.

> Rows describe current code. **Update the matching row in the same commit as the code it describes** — a stale row is worse than none. Index of all maps: [../../CLAUDE.md](../../CLAUDE.md) → "Find it fast".

| Goal | File(s) |
|---|---|
| **Workouts** | |
| Add exercise | `Data/Repositories/Repositories.swift` → `Repos.createExercise` |
| Add-exercise sheet | `Features/Workouts/WorkoutsView.swift` → `AddExerciseSheet` — ONE sheet, one field set for everyone: name, reps/duration, isometric, optional fixed weight (any non-hold; blank on a rep exercise = it logs through the rep counter, `Draft.tracksWeight` is derived from that, there is no toggle). Hands back an `AddExerciseSheet.Draft` normalised to a valid shape; the call site (`ExercisesCard`) owns the rep range + `Repos.createExercise`. Never add a second add-exercise sheet |
| Exercise ⓘ info sheet | `Features/Workouts/ExerciseInfoSheet.swift` → `ExerciseInfoSheet(exercise:profile:todayCount:todayKcal:)` — ONE sheet, same for every profile; opened from `ExercisesCard` rows (passes today's tally) and from the rep counter / isometric timer. Reads the live `ExerciseModel` row and this exercise's sets with two predicate-scoped `@Query`s, so a weight edit shows at once. Content priority: `Movement.postExerciseHint` → `ExerciseInfo.meta` → on-device AI (only when neither library knows the movement). Single `loadAIIfNeeded`. Two rows sit after the "Today" block: **Weight** (only when `loadLb != nil`, e.g. Lifted Baby · 30 lb · Update → inline field in the profile's unit, saved via `Repos.updateExercise`; guards the `Bool`, an invalid value stays open with a message, a no-change save writes nothing; the caption says past reps keep the weight they were done at) and **Your progress** (last day's reps-at-weight + best; opens `ExerciseProgressSheet`; "Nothing logged yet" when empty) |
| Isometric timer UI | `Features/Workouts/RepCounter.swift` → `IsometricTimerView` — 30/45/60/90s preset pills above the 5-second wheel (presets + fine control, same shape as the live-session picker). The hold counts UP past the target (a haptic fires once when the target is reached) and logs only on "Stop and log"; `holdSeconds` stores the seconds actually held, measured on the wall clock (a locked screen doesn't undercount). "Discard" or a stop inside the first second logs nothing; a forgotten hold auto-logs at 600 s. The session counters move only after a successful `Repos.addSet`. Same reference block as the rep counter: "Last time · <day> longest 50 s" (plus total when there were several holds) and a "Today longest … · +5 s vs last time" strip |
| Isometric calorie math | `Domain/CalorieEstimator.swift` → `caloriesForIsometric` |
| Rep counter | `Features/Workouts/RepCounter.swift` → `RepCounterView` — a wheel picker for the set's count (1–100 reps, or 1–180 min for a `.duration` exercise; same `.wheel` idiom as `IsometricTimerView`), starting on the most recent logged count across the exercise's whole history (else 10 reps / 5 min) and keeping its value after Save set — no tap-to-count buttons. Half-sheet (`[.medium, .large]`, content in a `ScrollView`). Progress is **reps at a weight over ALL history, no sets** ([progress-tracking-plan](../progress-tracking-plan.md)): one predicate-scoped `@Query` on userId + exerciseId (newest first) is folded once per data change (`HistoryFold`) by `Domain/RepHistory.swift`, and a second `@Query` reads the live exercise row so a load edited in the ⓘ sheet on top is never stamped stale. Shows "Last time · <day>" and "Last week · <day>" (same weekday 7 days ago, else the nearest logged day in that ISO week, else "not logged") **at the weight in the field**; a reference day that didn't use that weight shows its top weight plus a note ("50 lb: 26 reps on Oct 2" / "not done before"); no earlier day reads "First time here". The `ProjectionBar` strip is a running tally — "Today 18 reps @ 50 lb · 12 to match last time · +2 vs last week" — each delta flips to "+N" once passed; a shortfall is never a warning. The weight field (labelled optional, dumbbell/one-arm hint — the app doesn't model per-arm vs pair; calories ignore weight) pre-fills from the last weight EVER used for that lift (`RepHistory.lastWeightLb`), only when empty, keeps two decimals (52.5 stays 52.5) and never overwrites typing; a typed weight is canonical to 0.01 lb (`RepHistory.canonicalLb`) so metric and imperial entry of one weight fold into one line. Opened from every `ExercisesCard` row; the field shows only when `tracksPerSetWeight`, a `.duration` exercise counts minutes. A fixed-load exercise stamps its CURRENT load on every row (`fixedLoadLb(forRowWeight:holdSeconds:)`). The calorie strip (`EncouragementEngine.repProjection(setCalories:totalCaloriesToday:)`) prints the figure the set was stored with. After a successful `Repos.addSet` exactly one toast: a new best (`RepHistory.newBest` → `ToastCenter.newBest`) > the weekly-reps note (rep exercises only; see next row) > "Set saved" |
| Rep history engine (reps at a weight) | `Domain/RepHistory.swift` — phone-only, Foundation-only (NOT in the watch source list). Folds an exercise's `WorkoutSetDTO` rows per exact weight (`WeightKey`: stamped `weightLb`, else the exercise's `loadLb`, else bodyweight/nil; canonical 0.01 lb) into `Tally`s by day (`days`, `Dates.dayKey`) and ISO week (`weeks`, `Dates.startOfISOWeek`). Measure by shape: reps / minutes (`.duration`) / hold seconds (longest + total). Also: `lastTime`, `sameDayLastWeek`, `compare` (more / fewer / same / new weight / not done) with `deltaText` / `liveDeltaText`, `bests` (per weight, heaviest, longest hold; needs `minHistoryDaysForBest` = 2 earlier days; ties keep the earliest day), `newBest(after:exercise:rows:)` (nil for a back-fill, a repeat today or too little history — callers also skip edits and watch logs), `weeklyReps` / `weeklyNoteAnnouncement` (approaching ≥ 75% of last week · passed · best week needs `minWeeksForBestWeek` = 3 earlier weeks · first week back), `summary` ("50 lb × 30 · 55 lb × 8"). Pure, derived on read, nothing stored. Copy builders: `EncouragementEngine.newBestMessage` / `weeklyRepsMessage`. Tests: `RepHistoryTests` |
| New-best and weekly-reps toasts | `ToastCenter.newBest(_:formatWeight:)` and `ToastCenter.weeklyReps(_:profileId:now:defaults:)` (`.win` accent). Fired only from `RepCounterView.saveSet` and `ExercisesCard.quickLog`, after a successful write, never for `EditSetSheet` edits/back-fills, watch logs or holds. Order: new best > weekly note > the plain confirmation. The weekly note is once per kind per ISO week, remembered in UserDefaults `weeklyRepsNote.<profile uuid>` = `<Monday dayKey>|kind,kind` and advanced only when a toast actually shows; `Repos.weeklyReps(ctx,userId:now:)` re-reads the full history fresh. `quickLog` reads the exercise's full history with `Repos.setHistory(limit: 100_000)` because the card's own query holds only today + yesterday |
| Per-exercise progress view | `Features/Workouts/ExerciseProgressSheet.swift` → `ExerciseProgressSheet(profile:exercise:)` — THE one per-exercise history view, a `StatDetailSheet` host (`canLog: false`, `.large`). Opened from the Strength card rows on Progress and the "Your progress" row in `ExerciseInfoSheet`. Headline = latest day's reps at weight; By day / By week chart toggle (one series per weight, legend only when several; holds chart the longest hold, duration charts minutes; Y axis from 0); two comparison columns — Last time and Same day last week, the second swappable via a Menu to any day or week actually trained (a week compares the latest day's week-so-far); decreases print plainly ("4 fewer than Oct 14", neutral colour, no red); bests per weight (hidden until 2 earlier days); day list newest first (30 + "Show older days") whose rows open `SetHistorySheet` on that day. The fold is memoised (`ExerciseHistoryMemo`, hash of every row field); compare choice and chart granularity are plain `@State`, no AppStorage. `ProgressFormat` (weight/amount/day labels) lives here and is shared with `ExerciseInfoSheet` and `TrainingHistorySheet` |
| Edit a fixed load (baby's weight) | `Repos.updateExercise(_:id:name:loadLb:)` (`Data/Repositories/Repositories.swift`) — edits name and/or a fixed `loadLb` (0 < v ≤ `Repos.maxFixedLoadLb` = 1000; false with nothing written for a missing exercise, blank name, a load on an exercise with no fixed load, or a bad value). When the load really changes it first stamps that exercise's nil-weight non-hold rows with the OLD load in the same transaction, so history keeps the weight each rep was done at. UI: the Weight row in `ExerciseInfoSheet`. Every fixed-load row carries its load in `WorkoutSetDTO.weightLb` (rep counter, `ExercisesCard` +1, `SetHistorySheet` back-fill, watch `.logQuickSet` resolved phone-side — no wire change); `Repos.backfillFixedLoadWeightsOnce` (called from `Seeder.seedAll`, UserDefaults flag `backfill.fixedLoadWeights.v1`) stamped pre-existing nil-weight rows once with the then-current load. No schema change. Tests: `OurFitnessPersistenceTests/FixedLoadTests` |
| Edit / delete / back-fill a logged set | `SetHistorySheet(profile:exercise:dayKey:)` in `Features/Workouts/WorkoutsView.swift` — the ONE set editor, for any day: a 7-day strip (plus the opening day if older) switches days; tap a row → `EditSetSheet` (same file), trash = delete, "Add a set" → the same `EditSetSheet` with `isNew: true` (writes `Repos.addSet` on that day: now for today, else a minute after the day's last set, else midday; calories via `Repos.setCaloriesEstimate`). A fixed-load row shows its stamped weight ("· 30 lb") and the editor shows the weight field for it: an untouched field keeps the stored weight exactly (no whole-unit re-parse), a changed one is canonical to 0.01 lb, and a cleared field cannot drop a fixed-load stamp. Reached from the clock on every `ExercisesCard` row (today), from an exercise row in `TrainingHistorySheet` (that day) and from a day row in `ExerciseProgressSheet`, so don't add a second one. Writes `Repos.updateSet` / `Repos.deleteSet`; "Delete … and all its sets" (confirmed) = `Repos.deleteExercise`; press-and-hold on an `ExercisesCard` row raises the same confirmed delete as a shortcut. Edits and back-fills never toast a best |
| Per-set calories (log, edit, preview, watch) | `Domain/ExerciseCalories.swift` → `CalorieEstimator.caloriesForSet(exercise:reps:holdSeconds:bodyWeightLb:loadLb:)` — THE per-set estimate, dispatched on exercise SHAPE, never goal: hold → `caloriesForIsometric` + `ExerciseInfo` MET; `.duration` → `caloriesForDuration` (reps = minutes); fixed `loadLb` → flat `caloriesForReps(reps:loadLb:)`; else `caloriesForReps(reps:exercise:)`. The optional `loadLb` override (default nil = the exercise's current load; honoured only on a fixed-load exercise) lets a re-priced old row point at its own stamped load; today the flat estimators read only whether a load exists, so it is numerically inert. `ExerciseDTO.fixedLoadLb(forRowWeight:holdSeconds:)` resolves it (nil for holds and for exercises with no fixed load; else the row's weight if > 0 and finite, else the exercise's load). Phone callers go through `Repos.setCaloriesEstimate(exercise:reps:holdSeconds:bodyWeightLb:loadLb:)` (rep counter, hold timer, `ExercisesCard` +1, `EditSetSheet` preview, `Repos.updateSet` recompute from the row's stamped weight); `WatchSyncService`'s quick-set and `ExerciseInfoSheet` call `caloriesForSet` directly. Never re-branch the math at a call site. Tests: `SetEditCaloriesTests` |
| Exercise shape (which controls a row gets) | `Domain/Models.swift` → `ExerciseDTO.tracksPerSetWeight` (reps, no `loadLb`, not isometric, compound/isolation → rep counter with weight field) / `isOneTapLoggable` (not isometric, not tracksPerSetWeight → inline +1, and the watch quick-log filter). Isometric → hold timer. Read these predicates; never branch on goal. `RepHistory.measure(for:)` / `isRepExercise` map the same shapes to reps / minutes / hold seconds for history and weekly reps |
| Log pilates | `Repos.logPilatesSession` + `Domain/Models.swift` (`PilatesSessionDTO`). ONE manual form: `LogPastSessionSheet` in `Features/Workouts/LiveSessionCard.swift` (focus-area chips + notes appear when the chosen activity is Pilates). `Features/Workouts/ActivitySectionCard.swift` (`section: .pilates`, an optional Train section — see next row) is ring/streak/weekly goal + "Log Pilates" only — NO session list — and opens that sheet via `lockedActivityId: section.activityId`; a live session with the Pilates activity writes only a `PilatesSessionDTO` (`Repos.completeLiveSession`), so it lists once. Never add a second Pilates form or give `ActivitySectionCard` its own list. Today/yesterday Pilates sessions are listed, edited and deleted in `RecentActivitySessions` (see next row) |
| Optional Train sections (Pilates / Yoga / Stretching) | `Domain/TrainSections.swift` (`TrainSection` metadata + goal keys; `TrainSections.enabled/available/encode`; `countThisWeek` / `weeklyStreak`) + `Features/Workouts/ActivitySectionCard.swift` — ONE card for every section (ring of sessions this week vs weekly goal, streak, "Log <section>" → `LogPastSessionSheet` locked to the activity). Pilates reads `PilatesSessionModel`; Yoga/Stretching read `ActivitySessionModel` scoped by `activityId`. Enabled set = AppStorage `trainSections.<uuid>` CSV: "" (never set) → sections with logged data (existing Pilates users keep their card), "none" = explicitly empty. Pilates keeps goal key `pilatesWeeklyGoal.<uuid>`. Add = "Add a section" pills in `WorkoutsView`; remove = press-and-hold (context menu) → confirm; logged data is kept. Tests: `TrainSectionsTests` |
| Edit a logged session's duration | `EditDurationSheet` in `Features/Workouts/LiveSessionCard.swift` — ONE duration editor, used only by `RecentActivitySessions` (same file) — THE today/yesterday session list on Train, covering `ActivitySessionDTO` (writes `Repos.updateActivitySession`, which recomputes `caloriesEst` from the stored MET; delete `Repos.deleteActivitySession`) and `PilatesSessionDTO` (writes `Repos.updatePilatesSession`; Pilates stores no calorie figure, the burn is derived on read via `caloriesForPilates`; delete `Repos.deletePilatesSession`). Caller owns the preview + the write and returns false on failure so the sheet stays open. Deleting a session: the trash button or a press-and-hold on the row's info area raises ONE `confirmationDialog` (`pendingDelete`); no context menu. Train is the home for correcting today/yesterday sessions — Progress › Training history stays the cross-day read + delete surface |
| Log cardio (run / bike / swim / row / hike) | `LogPastSessionSheet` in `Features/Workouts/LiveSessionCard.swift` — "Log session" on `LiveSessionCard` (Train tab). Saves an `ActivitySessionDTO` with the activity's Ainsworth MET from `Domain/ActivityCatalog.swift`. There is no separate cardio logger: `CardioSessionDTO` is legacy read-only (see Data model) — never add one back |
| Exercise list (Train tab) | `Features/Workouts/ExercisesCard.swift` — THE one list of every exercise the profile owns (lifts, holds, quick-log movements, each once), A→Z, with a `ProgressRing` header (distinct exercises logged today / total + today's burn). `WorkoutsView` order: `LiveSessionCard` → `ExercisesCard` → "Training history" row → enabled `ActivitySectionCard`s (Pilates, Yoga, Stretching) → "Add a section" → "what should I work on?". Row controls come from shape: isometric → hold timer; `tracksPerSetWeight` → rep counter; `isOneTapLoggable` → inline +1 (+1 min for duration; a fixed-load movement stamps its load on the row; toasts a new best or the weekly-reps note, else the plain "+1"), row tap still opens the rep counter. The inline undo removes only sets that +1 created in this view's lifetime (`quickLoggedSetIds`) — never a rep-counter set; anything older is corrected via the clock. Every row: clock → `SetHistorySheet` · ⓘ → `ExerciseInfoSheet`. Deleting an exercise: press-and-hold the row body (`simultaneousGesture(LongPressGesture(minimumDuration: 0.5))` on the two row-body buttons only → one `confirmationDialog` attached per row and keyed off the card's single `pendingDelete`, so the iOS 26 popover points at that row; `Haptics.warn()` fires once when the hold is recognised; the release tap is ignored while `pendingDelete` is set) or the confirmed action in `SetHistorySheet` — rows sit in a `Card`'s VStack, where `.swipeActions` is a silent no-op. Sheets hang off the list, not the rows |
