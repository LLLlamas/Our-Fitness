# Map: Today, Steps, Water, nudges

Today status board: Move card, Steps card, water tracker and quick-log, burn estimate, encouragement/milestones, meal/water nudges, learned-timing meal push reminders.

> Rows describe current code. **Update the matching row in the same commit as the code it describes** — a stale row is worse than none. Index of all maps: [../../CLAUDE.md](../../CLAUDE.md) → "Find it fast".

| Goal | File(s) |
|---|---|
| **Today / Steps** | |
| Move card (steps + 2×3 cols) | `Features/Today/MoveCard.swift` — top of Today. Generic over a `steps` `@ViewBuilder` slot: `TodayView` passes the one `StepsCard(embedded: true)`, rendered at the top of the card; then row 1: Apple Total · Our Total Estimate · Training Only; row 2: Distance · Flights · Heart Rate. MoveCard draws **no step figures of its own** — the slot is the `StepsCard` (an earlier steps row duplicated its count, goal, goal-picker and info sheet, plus a stale gross-MET formula string). Single `metricColumn` helper (uniform 22pt value font, no differential shrink). `activityRow(kcal:)` takes `Int`. Burn figures come from `DailyBurn.breakdown` (never re-derive MET math or the step-overlap exclusions here — `countedCardio` / `countedActivities` read `DailyBurn`'s sets); unit conversions via `Units.kgPerLb` / `Units.kmPerMile`; the 7 column info sheets sit on `Components/InfoSheet.swift`. Move only renders when `profile.healthGranted` — ungranted, `TodayView` shows `connectHealthCard` at the top instead; that card is the ONLY Health-connect surface on Today (`StepsCard` has no Connect pill) |
| Steps card (Today only) | `Features/Today/StepsCard.swift` — one card, the same for everyone; `embedded: true` inside `MoveCard` (no card chrome, title "Steps"), standalone before Health is connected: `ProgressRing` + projection + pace-vs-yesterday + 7-day strip + week-to-date active cal / exercise min + weekly streak chip + milestone toasts. One goal-picker sheet (shared `Components/GoalPickerSheet.swift`; daily-target + days/week wheels) + one info sheet (`StepsInfoSheet`, on `Components/InfoSheet.swift`). The goal only sets the default daily target (`computedTargets.stepsDaily`). Goal keys live in `StepsGoalPrefs` in the same file; `StepsGoalPrefs.resolve(custom:goalDefault:)` (stored 0 = no override) is the one resolver, shared with `TodayView`'s streak math. Never add a second steps card |
| Water tracker (presets + day-streak) | `Domain/Water.swift` (presets Sip 4 / S 8 / M 16 / L 32 oz; `total(_:on:)`, `streak(_:goalFlOz:end:)`) + `Features/Today/WaterCard.swift` (streak chip = shared `Components/StreakChip.swift`; the card header is the only "WATER" label — the bar row reads "TODAY") |
| Log water (shared path — use for ANY new water surface) | `Features/Today/WaterLogging.swift` → `WaterLog.add(_:for:on:context:lastFlOz:unitSystem:toasts:)` — one write + remembers the repeat-last amount + one copy of the toast; also owns the `waterGoalFlOz.\(profileId)` / `waterLastFlOz.\(profileId)` AppStorage keys. No explicit haptic (ToastCenter.show fires one) |
| Water quick-log (app-wide FAB) | `Features/Today/WaterQuickLogButton.swift` — tap = repeat last, press-and-hold = dim screen + radial preset picker; logs via `WaterLog.add`. Overlaid in `App/RootView.swift` |

Net of resting — see [calorie-math.md](../calorie-math.md). The step-overlap exclusions live here as `stepOverlappingCardio` / `stepOverlappingActivityIds`. Tests: `OurFitnessTests/DailyBurnTests.swift` |
| Encouragement / milestones | `Domain/EncouragementEngine.swift` + `Domain/EncouragementMessage.swift` + `Components/ProjectionBar.swift` |
| Meal/water nudges | `Domain/EncouragementEngine.swift` → `mealLoggingNudge` / `waterNudge`; wired in `Features/Today/TodayView.swift` through `ToastCenter.mealNudge` / `waterReminder`, which compute the message once and return whether they showed (the hour guard advances only on `true`) |
| Meal-logging push reminders (learned timing) | `Domain/MealLogPattern.swift` — breakfast/lunch/dinner only; median of each day's earliest REAL-TIME log (timestamp day == `date` key) over 14 days, today excluded; needs 4 days before scheduling or display; no fallback defaults; +60 min grace; quiet hours 22:00–06:00; plans today + 2 days (≤ 9 requests), skips a slot already logged that day; wall-clock components (DST). Tests: `MealLogPatternTests`. Scheduling `Services/MealReminderService.swift` (activated in `OurFitnessApp`), opt-in per profile `mealReminders.enabled.<uuid>` (default off); ids `mealLog.<day>.<slot>` (never `reminder.`, so `reconcile` won't prune them and `willPresent` keeps them silent in foreground, where the in-app nudge covers it); re-plans on `.repositoryDidSave` (coalesced), foreground (`RootView`) and the Settings toggle; authorization ONLY from the toggle (`MealReminderService.enable`). Tap posts `.openMealsTab` → `RootView` selects Meals. Settings: "Meal logging reminders" + caption with learned times; the in-app toast toggle is "In-app meal nudge" (`nudge.meal.enabled`) |
