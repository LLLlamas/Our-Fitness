## Goal rules in detail

The goal table is in [CLAUDE.md](../../CLAUDE.md). This is the rest of the goal section, moved verbatim.

Every new profile gets three starter movements (`Repos.createProfile` → `seedStarterMovements`): Lifted Baby (30 lb), Lifted Stroller (25 lb), Carried Baby (30 lb, duration). Changing targets (`Repos.updateTargets`) never seeds; existing profiles aren't backfilled. Their weights are editable (ⓘ sheet → `Repos.updateExercise`) and every logged row carries the load it was done at in `weightLb` — see "Edit a fixed load" in [workouts.md](workouts.md). `Seeder.seedAll` also runs `Repos.backfillFixedLoadWeightsOnce` (once, UserDefaults flag `backfill.fixedLoadWeights.v1`) next to `backfillHeartHealthTargets`. Isometric exercises: `isIsometric: true` on `ExerciseDTO`; hold saves `WorkoutSetModel{reps:1, holdSeconds:N}`; calorie: `CalorieEstimator.caloriesForIsometric`.

| **HealthKit** | |
| New HK metric | `Services/HealthKitService.swift` + `Data/PersistenceModels.swift` |
| Sync Health into logs | `HealthKitService.syncFromHealth` (deduped upsert; re-points `profile.weightLb`) |
| Fasting glucose from Health | `HealthKitService.latestFastingGlucoseMgDL` — only samples HealthKit marks pre-meal (`HKMetadataKeyBloodGlucoseMealTime` == `.preprandial`) become `.fastingGlucose`; post-meal and metadata-less samples are **dropped**, because a normal post-meal 150 filed as fasting trips `HealthRanges` ≥126 → high (ADA diabetes cut-point). Storing them needs a new non-fasting glucose `HealthMarkerKind` |
| VO₂ max (cardio fitness) from Health | `HealthKitService.syncVO2MaxHistory`, called at the end of `syncFromHealth`. `.vo2Max` is in `readTypes`; unit `vo2MaxUnit` = `literUnit(with: .milli)` ÷ (`gramUnit(with: .kilo)` × `.minute()`), type-safe like the others. Every sync reads all samples from the newest stored `vo2_max` day, or 2 years back if none (`CardioFitness.historyStart`) — **no one-shot flag**, since a read before the user re-runs Connect comes back empty and must not end the backfill. Markers are fetched once, deduped in memory to one reading per day (`CardioFitness.newDailyReadings`, newest sample of the day), and inserted in one commit (`Repos.addMarkers`). Already-connected users must tap Connect again to grant the new type (Settings › Apple Health, or the tracker's empty state). Usage text: `OurFitness/Info.plist` `NSHealthShareUsageDescription` names cardio fitness (VO₂ max); edit the plist directly (no `info:` block) |
| Workouts from Health (cardio minutes) | `HealthKitService.refreshCardioWorkouts`, called at the end of `syncFromHealth` and from `ProgressTabView`'s `.task` (a read, only when `profile.healthGranted`). `HKObjectType.workoutType()` is now in `readTypes` as well as `writeTypes`. Every call re-reads all workouts that **started** since `CardioFitness.healthWindowStart` (Monday 11 weeks before this one — the tracker's 12 weeks); no one-shot flag. **Derived on read, never stored:** the mapped list (`CardioFitness.HealthWorkout`: start, end, `HKWorkout.duration`, kind, `sourceRevision.source.bundleIdentifier`) lives only in the `@Published cardioWorkouts` cache — chosen over a SwiftData model because the window is small and fully re-read each sync, so storage would add a schema bump and its own staleness/dedupe for no gain; cost: a cold launch that opens on Progress shows logged minutes only until the read returns. `workoutKind(_:)` maps `HKWorkoutActivityType` to `CardioFitness.WorkoutKind` (anything unlisted = `.other`, not counted). Own-app workouts are logged once per process (`[HealthKit] own-app workouts in Health stamped with source:`) because which bundle id a watch-saved workout carries is unverified. **Minutes only** — never burn, `DailyBurn`, energy balance or active energy. Already-connected users must tap Connect again (Settings › Apple Health, or the tracker's empty state). Usage text in `OurFitness/Info.plist` names workouts |
| Weekly Health totals | `HealthKitService.weekToDateBounds` → must use `Dates.startOfISOWeek` (Monday). Never `Calendar.current` week intervals — Sunday-first in the US locale, which desyncs the StepsCard week cells from every other weekly figure |
| Absent-data policy for HK sums | `sumOrNil` / `dailySums` return nil / omit the key so the UI can hide the stat; `dailySum` (single day) is the one place absent collapses to 0. Never fabricate a 0 for a day that simply never synced |

| Schema migration | `Data/Schema.swift` — current SchemaV7. Additive (new optional field / entity) = automatic. Structural = `.custom` stage. |
