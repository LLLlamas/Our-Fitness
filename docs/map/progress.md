# Map: Progress tab

Trackers, stat detail sheet, training volume, strength progress, tape measurements, weeks, energy balance, training history, BMI/body-fat thresholds.

> Rows describe current code. **Update the matching row in the same commit as the code it describes** — a stale row is worse than none. Index of all maps: [../../CLAUDE.md](../../CLAUDE.md) → "Find it fast".

| Goal | File(s) |
|---|---|
| **Progress** | |
| Add health marker kind | `Domain/Models.swift` (`HealthMarkerKind`) + `Domain/HealthRanges.swift` (exhaustive switches) + `Features/Progress/ProgressView.swift` |
| Show/hide trackers | `Features/Progress/EditTrackersSheet.swift` — `AppStorage "progressStats.\(profileId)"`. Default set = `StatKind.isDefault` (one set for every goal): weight / steps / Weekly Reps (`StatKind.trainingVolume`) / resting HR / blood pressure — trackers the app fills itself, plus BP as the one cheap self-measure; BMI (duplicates Weight) and everything needing calipers, a tape or a lab starts hidden. `ProgressTabView.enabledSet(body:markers:)` then re-adds any tracker that already `hasLoggedData`, so shrinking the default never hides a card someone was filling in. A stored CSV always wins. |
| Stat detail sheet (chart + entries + log) | `Components/StatDetailSheet.swift` — ONE sheet for every tracker. Metric-specific bits come in as slots (`headline`, `chartOverride`, `logOverride`, `footer`) plus `validate` / `showsEntries` / `minChartPoints` / `detents`; `StatDetailRow` is the shared label/value row. Weight (wheel picker), Body fat, BMI, and Blood pressure in `ProgressView.swift` are all thin hosts over it — never write another bespoke detail sheet |
| Training volume (tracker title "Weekly Reps") | `StatKind.trainingVolume` in `Features/Progress/ProgressView.swift` (raw value unchanged — the enabled set is a persisted CSV; only the title/unit changed). Value = reps this week, unit "reps · this week", chip "+N vs last wk"; shows 0 beside last week's total when this week is empty. Math: `Domain/TrainingHistory.swift` → `repsInWeek(_:exercises:weeksAgo:now:)` / `weeklyRepCounts(_:exercises:weeks:now:)` (Monday ISO weeks; rep exercises only — holds, minutes and unknown exercises excluded; a +1 tap counts its reps, not 1 "set") and `RepHistory.weeklyReps(sets:exercises:now:)` for last week, the one own-history note (`WeeklyNote`: approaching / passed / best week / first week back; copy `RepHistory.noteText`) and the per-exercise split. Detail = `WeeklyRepsDetailSheet` (a thin `StatDetailSheet` host): big number, last week, the note, "This week by exercise"; its ⓘ (`WeeklyRepsInfoSheet`) explains that research counts hard sets per muscle, so a reps total can't say "enough", and gives the ~80–120 reps ≈ 10 hard sets rule of thumb labelled as an estimate (the 10-set figure is unverified against the papers). The weekly-reps once-per-week TOAST is a rep-counter/`ExercisesCard` thing — see the Train map. `TrainingSummary` memoises the weekly and strength folds per data change. Tests: `TrainingHistoryTests`, `RepHistoryTests` |
| Strength card (every trained exercise) | `strengthCard` + `StrengthEntry` in `Features/Progress/ProgressView.swift` — hidden until something is logged; lists EVERY trained exercise, most recently trained first (top 5 + "Show all N"), each row showing the figure for its shape: weighted lift → estimated max (`≈`, labelled "estimated max"; Epley `weight × (1 + reps/30)` over sets of 1–`StrengthProgress.maxReps` (12) reps) from `Domain/StrengthProgress.swift` → `lifts(sets:exercises:now:)` (only `tracksPerSetWeight` exercises; `gainLb` = best estimate in the last 28 days minus the best before them, **can be negative** — printed plainly as "−N lb · 4 wk" in the neutral colour; nil for a lift not trained in the window or newer than it; `recentMaxLb` is the window best); bodyweight or a lift with no countable weighted set → best reps in a day; fixed-load movement → best reps in a day at its current load; `.duration` → best minutes in a day; hold → longest hold. A row is its own button (a plain `Card`, not a `PressableCard`, so each row gets its own tap) and opens `ExerciseProgressSheet` (see the Train map). Fixed-load rows are included via their stamped `weightLb`, but `StrengthProgress` still filters on `tracksPerSetWeight`, so they never get an Epley estimate. Tests: `StrengthProgressTests`, `RepHistoryTests` |
| Tape measurements (frame size: waist, shoulders, chest, arm, thigh) | `StatKind` in `Features/Progress/ProgressView.swift` — ONE code path for all five via `StatKind.tapeIn` (a `WritableKeyPath` into `BodyMetricDTO`); values stored in canonical inches on `BodyMetricDTO.{waistIn,shouldersIn,chestIn,armIn,thighIn}` (+ `BodyMetricModel`), converted at the UI boundary. New StatKind cases are appended last (the enabled set is a persisted CSV). All start hidden (`isDefault` false) and re-appear automatically once logged. The four new columns are optional/additive and shipped WITHOUT a schema version bump (same pattern as earlier optional fields; container opens `AppSchema.current` directly). Upgrade verified on the simulator — see the Oct 2026 validation record |
| Weeks ("this week") | `Domain/Dates.startOfISOWeek(_:weeksAgo:)` — Monday-anchored, the app-wide definition. Never `Calendar.current` week components (Sunday-based in the US). `Domain/Movement.swift` still builds its own Monday calendars — migrate it to this helper when touched. Tests: `DatesTests` |
| Calorie intake vs activity burn | `Domain/EnergyBalance.swift` → `byDay(...)` / `averages(_:)` (intake = `DailyTotals`; burn = `DailyBurn.metEstimate` — active-only, step-overlapping sessions excluded). Card `energyBalanceCard` (both modes) in `Features/Progress/ProgressView.swift` → detail `Features/Progress/EnergyBalanceDetailSheet.swift` (Charts: intake bars vs burn line + target rule). Tests: `OurFitnessTests/EnergyBalanceTests.swift` |
| Training history (cross-day) | `Domain/TrainingHistory.swift` → `sessions(sets:exercises:)` strength grouping (each `ExerciseLine` carries `tally: RepHistory.Tally`, `totalReps`, `totalHoldSeconds`, `calories`, `setIds`; `DaySession.totalSets` is the logged-row count) + `Features/Workouts/TrainingHistorySheet.swift` for strength, live, cardio, and Pilates sessions — opened from Train and Progress; an exercise row reads reps-at-weight (`RepHistory.summary` → "50 lb × 30 · 55 lb × 8", then the day's burn), the day header says "N exercises", and the row opens `SetHistorySheet` on that day. Tests: `OurFitnessTests/TrainingHistoryTests.swift` |
| Tracker display order | alphabetical by `StatKind.title` at the two render sites (`visibleStats(in:)` + `EditTrackersSheet` ForEach); never reorder the enum (persisted CSV) |
| Latest value of a health marker | `Trends.markerSeries(_:kind:).last?.value` — via the single `latestMarkerValue` helper in `ProgressView.swift`. Don't re-filter/sort markers inline |
| BMI / body-fat thresholds | `Domain/BodyComposition.swift` → `bmiCategory` / `bodyFatCategory` own every boundary. The Progress sheets read labels from them (`bmiIsHealthy`, the probe-value range tables); never restate 18.5 / 25 or a body-fat band in a view |
